## PWA（第4フェーズ）

### 相対パス設計 — ホスティング先が未定でも動く
配信先がルートでもサブパスでも同じ dist/ がそのまま動くよう、**すべて相対パス**にしてある。

- manifest: `start_url: "./"`、`scope: "./"`
- head: `<link rel="manifest" href="./manifest.webmanifest">` など
- SW登録: `navigator.serviceWorker.register('./sw.js')`
- SW内のアセット参照: `new URL('./index.html', self.location)` で解決

`make-pwa.js` は出力前に、絶対パス参照（`/` 始まりや `http://` 始まり）が
混ざっていないか検査して落ちる。

### アイコン
`src/mkicon.js` が依存ライブラリなしで生成する（PNGエンコーダも自前）。

| ファイル | 用途 |
|---|---|
| `icons/icon-192.png` | manifest `purpose: "any"` |
| `icons/icon-512.png` | manifest `purpose: "any"` |
| `icons/icon-maskable-512.png` | manifest `purpose: "maskable"`。**別デザイン** |
| `icons/apple-touch-icon.png` | iOS ホーム画面（iOSはmanifestを見ないので別途必要） |

maskable は図柄を `k=0.78` に縮めて中央80%の円（セーフゾーン）に収め、
背景は角まで塗りつぶしてある。`any` を流用すると角が切られる。
生成時に「図柄の最外周 = 半径0.782 ≤ 上限0.80」を検査し、超えたら落ちる。

### dist/ と docs/ の関係
`docs/` が GitHub Pages の公開ディレクトリで、git 管理下にある
（`dist/` と `solar-system.artifact.html` は `.gitignore` 済み）。

**`make-pwa.js` は dist/ を作ったあと docs/ へ自動で同期する。**
手作業のコピーに頼ると、修正がビルドされていても公開版に届かないまま
放置される事故が起きるため（実際に一度その状態になった）。
`docs/.nojekyll` は同期時に消さず残す。

### Service Worker のキャッシュ更新の仕組み
ここを間違えると更新が二度と届かなくなるので、仕組みを明記しておく。

1. `make-pwa.js` が **index.html・manifest・全アイコンの中身**から SHA-256 を取り、
   先頭12桁を `VERSION` として `sw.js` に埋める。キャッシュ名は `solar-<VERSION>`
2. どれか1バイトでも変われば VERSION が変わり、`sw.js` 自体の中身も変わる。
   ブラウザは `sw.js` のバイト差分で更新を検知する
3. `install` で全アセットをプリキャッシュする。**`skipWaiting` は呼ばない**
   （黙って入れ替えず、本人に選ばせる）
4. 新しい SW が `waiting` になったらページ側が**更新バナー**を出す。
   「再読み込み」で `postMessage({type:'SKIP_WAITING'})` → `controllerchange` → `location.reload()`
5. 新しい SW の `activate` で、接頭辞 `solar-` が同じで名前の違う
   **古いキャッシュをすべて削除**してから `clients.claim()`

補足:
- 初回インストール時は `controllerchange` で再読み込みしない（`hadController` で更新と区別）。
  リロードループを防ぐため
- `controllerchange` が来ない環境向けに 2.5秒のタイムアウト保険がある
- `file://` では SW を登録できないので、失敗しても握りつぶして通常動作を続ける
  （単一ファイル版の導線を壊さないため）
- SW は**同一オリジンの GET しか扱わない**。外部通信は一切しない
- ナビゲーションはオフライン時に `index.html` へフォールバックする
- プッシュ通知・バックグラウンド同期は入れていない（このアプリに不要）

## ★ 50音歴の定義（将来の再現に必須）

**冬至（太陽黄経270°）を起点とし、太陽黄経が 7.2° 進むごとに次の音へ移る定気法。**
360 ÷ 50 ＝ 7.2 なので、必ず冬至でちょうど一巡して1番目に戻る。

```
ホ オ ヲ ヘ エ ヱ フ ウ ゥ ヒ
ミ イ 井 ハ ア ワ ヤ ィ ユ ェ
ヨ ノ ネ ヌ ニ ナ ラ リ ル レ
ロ コ ソ ケ セ ク ス キ カ シ
サ タ チ ツ テ ト モ メ ム マ
```

1番目「ホ」が冬至から始まる区間。**「井」は「ヰ」に正規化しない。**
実体は `src/calendar-core.js` の `GOJUON` と `GOJUON_STEP`。

**各音に意味・属性・対応表は一切持たせていない。音と日付だけを出す。**
ここはユーザーの領域。**この方針は変更しないこと。**

## ★ 人物理解機能の主従の構造（第5フェーズで作り直し・最重要）

### 三層の主従

```
主   = 法則（真理構造）
従1  = 生年月日・暦記号・星の配置       ← 法則が現れた一つの面
従2  = 生活・履歴・環境・選択・行動     ← 法則が展開したもう一つの面
```

**法則を従1に照らし合わせて、従2に何が展開しているかを読み解く。**
これがこの機能の本質。従1と従2はどちらも法則が展開した面であり、対等な「従」。

第4フェーズまでは「本人の生活が主／暦記号が従」という二層だったが、
本人の訂正により三層へ作り直した（2026-08-13）。

### 食い違ったときの扱い

読みの出力と本人の実際の出来事が食い違ったとき、**法則側を優先する**。
これは本人が、反証不能になるという指摘を受けたうえで明示的に選択した設計。

ただし実装は次の形に限定している。

- 食い違いを「本人が間違っている」「気づいていないだけだ」とは**書かない**。
  人に向かって「君は自分を分かっていない」と言う構造にはしない
- 代わりに「**法則の展開が、いま見ている面には出ていない可能性**」
  「**照らしている面が違う可能性**」として扱う。
  ずれているのは法則ではなく、どの面を見ているか、という書き方
- 本人の観察は引き続き記録できる。記録を失わせない

### status（面の見え方の記録）

```
まだ見ていない / この面に出ている / 別の面に出ている / 判断がつかない
```

旧 `未検証 / 本人が支持 / 反証あり / 混合` は法則を反証する建て付けだったので置き換えた。
**「反証あり」は消していない**。`別の面に出ている` として、本人が見た事実は残る。
保存済みの旧キーは `RC.STATUS_MIGRATE` で自動的に読み替える（記録を失わせないため）。

### タグ

`[計算] [伝統] [読み] [確認] [別面] [不能]`。
`[反証]` を `[別面]`（この面には出ておらず、別の面に出ていた）へ意味ごと変更（第5フェーズ）。
`[仮説]` を `[読み]` へ変更（第7フェーズ。理由は下の「文体と構成」節）。

## ★ 人物理解の文体と構成（第7フェーズ・最重要）

### 断定調にした理由

第5フェーズで **主＝法則** に変えた以上、「〜かもしれない」「〜という仮説」という
慎重な言い回しは構造と食い違う。法則が主なら、読みは断定で書くのが整合する。
本人の示した参考文体（「日干は辛金。本質は、宝石・刃物・精密金属のような人です」
「見抜く力が非常に強い人です」）に合わせて全文を書き直した。

**ただし断定してよいのは、採用した象意と生剋の関係から導けることだけ。**
導けないものは推測で埋めず `[不能]` に置く。この線は一切ゆるめていない。

### バーナム文を防ぐ仕掛け（機械検査あり）

断定調は抽象的な一般論に流れやすい。そこで**構造で縛った**。

- 断定文（`.say` / `.beat`）は、必ず根拠ブロック（`.rd > .src`）を持つ
  `.rd` の中にしか置けない
- `.src` には必ずタグチップ（`[計算]` か `[伝統]`）と、命式のどの記号から
  来たかが入る（例: 「日干は辛。陰の金。象意は『宝石・刃物・精密金属』」）
- **描画された実出力に対して**「根拠を持たない断定が0件」を検査する。
  1969-10-03 では断定42件すべてが根拠つき、39通りの生年月日でも0件

### 10節の構成

```
1 基本命式（表＋採用した流派・表・境界）
2 四柱推命で見る本質（日主・月令・支の重なり・日柱）
3 五行の偏り（何が厚く、何が無いか、それが何を生むか）
4 算命学で見る本質（十大主星・十二大従星。配置は出さない）
5 天中殺（算術事実＋そこから言えること）
6 宿曜道で見る本質（採用方式を明記）
7 真理構造からの統合
8 向いている場・役割
9 一言でまとめると（＋中心目的の候補の問い）
10 見えていない部分（[不能] の列挙）
```

### 五行の偏りで採用した規則

| 項目 | 採用 |
|---|---|
| 五行の数え方 | 四柱それぞれの**天干と地支**の五行を1つずつ数える。**蔵干は数えない**。時柱が無ければその分だけ合計が減る |
| 五行の関係 | **相生と相剋だけ**（木生火生土生金生水生木／木剋土剋水剋火剋金剋木） |
| 欠けた五行の読み | `[日主の五行] × [欠けた五行の日主に対する関係]` の 5×4＝20 通りの表。「金日主に火が無い＝鍛える火が無いので冷たいまま硬くなる」はここから出る |
| 月令に対する位置 | **旺相休囚死**（当令者旺・令生者相・生令者休・剋令者囚・令剋者死） |

**採用しなかったもの（推測で埋めなかった箇所）**

- **調候用神・喜神・忌神の判定** → 決め方が流派で違うため。
  「この五行が吉」という言い方は一切していない
- **身強・身弱の判定** → 月令・通根・蔵干の重みづけが流派で違うため。
  旺相休囚死までは出すが、そこから強弱を断定しない
- **格局**（建禄格・従旺格などの判定）→ 同上

### 参考文章から採用しなかったもの

本人の示した参考文章には次の3点が含まれていたが、**採用していない**。

| 参考文章にあったもの | 採否 | 理由 |

### パネル内の文字サイズ（第6フェーズ）
本人の要望「スマホの文字を指操作で拡大、縮小できるように」への対応。

**ブラウザ標準のピンチズームは解禁していない。** 理由は2つ。
この画面は全面 `position:fixed` + `overflow:hidden` なので、ページ全体が拡大すると
端が見えなくなって元に戻せなくなる。加えて、星図のピンチは惑星ズームに使っており衝突する。
`user-scalable=no` と星図の `touch-action:none` はそのまま維持している。

代わりに **アプリ内の文字倍率** として実装した。

- `:root` の `--tscale`（既定1）を、パネル内の `font-size` すべてに `calc(Npx * var(--tscale))` で掛ける
- 範囲 **0.8〜2.0倍**、連続。範囲外は端で止まる
- **パネル内の2本指ピンチ**で倍率変更。2本指の距離の比をそのまま掛ける
- **1本指は素通し**（`preventDefault` しない）＝今までどおりスクロールできる。
  2本指のときだけ `preventDefault` して横取りする
- 各パネルのヘッダに `A−` / 倍率表示 / `A＋`。倍率表示のタップで100%に戻る
- 文字が大きくなったときに中身が入りきるよう、`.sel select` の高さ、入力欄の `min-height`、
  状態ボタンの `min-width`、50音の文字枠なども同じ倍率で伸ばしている

**対象**: `#read`（人物理解／必須要件）、暦シート、`#sheet`（天体情報）、`#birth`（生年月日入力）の4パネル。
**対象外**: 星図・上部HUD・下部コントロール（固定レイアウトなので拡大すると崩れる）、
キャンバスに描く惑星ラベル、各パネルの閉じるボタン（×）と `details` の▾（文字ではなくアイコンのため）。

**保存**: 倍率は `localStorage` の **`solar.tscale.v1`** に常時保存する。
生年月日の保存オプトイン（`solar.birth.v1`）とは**別キー**で、表示設定なのでオプトインの対象外。
「保存された入力を削除」ボタンでも**消えない**（消すと文字が小さく戻って驚くため）。

JS が組み立てる本文にインラインの `font-size` が21箇所あったが、
倍率の取りこぼしが起きるので `.big` `.sub` `.subq` `.lead` のクラスに集約した。

### 出生時刻の入力UI（第5フェーズで変更）
`<input type="time">` は**使わない**。OSの時計ピッカーが開くが、確定の作法が
端末ごとに違って（iOSは確定ボタンがなく枠外タップ、Androidは文字盤のOKが見つけにくい）
実機で「確定できずに詰まる」報告があったため。

代わりに「時」「分」の2つの `<select>` にしてある。
- 時 = 0〜23、分 = 0〜59。**分は1分刻みで全部出す**（節入り境界の判定に効くので間引かない）
- 両方の先頭が「— 時（不明）」「— 分（不明）」で、**これが既定**。
  未選択のままなら今までどおり時刻不明として扱い、時柱・真太陽時・節入り境界を出さない
- 選択中の値は常に下に文字で出す（`出生時刻: 09:30` / `出生時刻: 未入力（時柱は出しません）`）

**片方だけ選ばれた場合は、足りない側を0で埋めずに先へ進ませない。**
「時と分の両方を選んでください」と警告を出し、足りない側にフォーカスする。
`09時` だけ選んだ人が `09:00` 生まれとは限らず、0で埋めるのは推測値の生成にあたるため。
このアプリは推測値を作らないことを最優先にしている。

`<input type="date">` はそのまま。日付は選ぶと即座に欄へ反映されて値が常に見えており、
時計ピッカーのような「確定できたか分からない」状態にならないため。
年月日を3つのselectにすると年の選択肢が200件近くになり、かえって扱いにくい。

時刻が不明のまま誕生時へ移動した場合、図の表示には便宜的に正午を使うが、
バッジは「**誕生日（時刻不明・正午で表示）**」と出して、正午を出生時刻と
誤解させないようにしている（時刻が分かっている場合は「誕生時」）。

### タップ設計の判断（記録）
惑星タップは**中心切替を優先**。情報パネルは画面の約6割を覆うため、切替と同時に開くと
「いま見たかった切替後の図」が隠れる。情報は ⓘ か「もう一度タップ」に逃がした。

### 誕生時ロックの仕組み
`pinnedMs` が非nullの間は端末時計を追いかけない。1倍速ならその瞬間で静止し、
倍速にすればそこから動き出す。バッジは紫の「誕生時」。「今」ボタンで解除。

### プライバシー
生年月日は端末外に出ない（アプリは一切通信しない）。localStorageへの保存は
**既定オフのオプトイン**。「保存された入力を削除」ボタンあり。動作確認済み。
